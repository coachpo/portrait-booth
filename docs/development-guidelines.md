# 开发规范

## 通用规模与职责规则

源代码规模、职责边界、长文件审查和拆分要求以[源代码规模与职责规则](源代码规模与职责规则.md)为准。

本文件不重复或改写该专项规则中的通用阈值。

共享开发工作流、设计与实现原则和完成定义以[贡献指南](../CONTRIBUTING.md)为准。组件职责、系统边界和依赖方向以[架构说明](架构说明.md)为准。

## 文件与格式

- 使用 UTF-8、LF 和一个结尾换行。
- Markdown、JSON 和 YAML 使用两个空格缩进；源代码由所选语言的项目格式化器管理。
- 在框架没有更强约定时，文件名使用描述性的 lower-kebab-case。
- 模块保持单一主职责；注释说明决策、限制或失败模式，不复述代码。

## 目录与测试

- 当前没有运行时目录。首个实现优先使用 `src/` 放置运行时代码、`tests/` 放置镜像测试、`assets/` 放置静态资源；若框架有成熟惯例，采用框架惯例并同步更新架构文档。
- 新行为必须有自动化测试；缺陷修复必须加入能复现问题的回归用例。
- 不得削弱断言、屏蔽合法错误或删除必要行为来使检查通过。
- 引入首个工具链时必须提供稳定的开发、测试、检查和构建命令。

## Portrait Booth 实现规则

- 上传文件、摄像头帧、脸部几何和编辑状态默认留在浏览器；只有用户明确选择暂存时才上传终态照片。
- 摄像头权限只能由用户操作触发；离开拍摄流程时必须停止所有媒体轨道，并保留上传与手动路径。
- 编辑采用非破坏性参数；预览、导出和暂存共享同一变换数学与终态工件。
- 模板规则必须版本化并指向官方来源；渠道不适用或未经复核的模板不能显示为可提交成品。
- KEY 按 6 位 `[A-Z0-9]` 字符串处理，保留前导零，使用无偏 CSPRNG 生成且永不复用；不得进入 URL、公开对象路径或日志。
- 服务端图片输入必须实际解码、限制资源并重新编码；不得信任文件扩展名、MIME 或客户端模板声明。
- 日志、遥测和错误追踪不得包含照片、KEY、访问或删除凭证、人脸关键点、对象路径或请求正文。
- 任何“通过”结果只能描述已检查项目，不能宣称政府认可或保证获批。

## 安全与配置

- 不提交凭据、私密媒体、本地环境文件或生产数据。
- 新增配置时提供去敏的 `.env.example`，并说明每个变量的用途，不包含真实值。
- 新依赖必须与当前范围直接相关，使用锁定版本，并纳入适用的漏洞与回归检查。
